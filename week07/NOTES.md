# 7주차 배운 것 (Claude 정리)

## 임베딩
- 임베딩 = 문장을 의미 공간의 좌표(벡터)로 변환. bge-m3 기준 1024차원
- 뜻이 비슷한 문장 = 가까운 좌표. "가까운 점 찾기"가 곧 "비슷한 의미 찾기"
- 생성 모델(qwen2.5)과 임베딩 모델(bge-m3)은 다른 전문직 — 임베딩은 전용 모델을 쓴다
- bge-m3 선택 이유: 로컬·무료·한국어·Ollama 지원의 교집합 (nomic-embed-text는 영어 중심)

## chromadb
- 벡터 DB = 벡터 저장 + 최근접 검색 전용 창고. chromadb는 SQLite 포지션(임베디드, 서버 불필요)
- 규모 커지면 서버형(Qdrant 등)으로 — 기준이 바뀌면 도구도 바뀐다
- collection(테이블 격) → add(ids, documents, embeddings) → query(query_embeddings, n_results)
- distances: 작을수록 가까움(비슷함)

## 실험에서 배운 것 (핵심)
- **키워드 없이 의미로 찾는다**: "휴가"→"연차", "회사 카드"→"법인카드" 매칭 성공 (Ctrl+F는 0건)
- **랭킹은 근사치**: "휴가 며칠?"에서 재택근무(0.795)가 연차(0.894)를 근소하게 이김 —
  임베딩은 의미 분위기를 잡지, 질문의 핵심 의도를 정확히 아는 게 아니다
- → RAG 설계 원칙: 상위 3~5개를 넉넉히 가져와 LLM에게 주고 최종 판별은 모델이 한다
  (검색은 그물, 모델이 고기를 고른다)
- **거리 = 신뢰도 신호**: 명확한 질문은 0.4~0.5 + 큰 격차, 애매하면 0.8대끼리 밀집 —
  "모르겠습니다" 판단 재료로 쓸 수 있음
