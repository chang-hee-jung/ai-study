# 4주차 배운 것 (Claude 정리)

## 왜 JSON인가 (체크포인트 답)
- 자유 텍스트는 사람용, 프로그램이 다루려면 구조가 필요하다. 모델이 매번 형식을 바꾸면
  (글머리 기호 변덕, "决定事项：" 언어 변덕) 후처리 코드가 깨진다 → 처음부터 데이터 구조로 받는다
- **부탁 vs 강제**: 프롬프트("JSON으로만 답해")는 확률을 높일 뿐. `format=스키마`는
  생성 단계에서 다른 형태가 불가능하게 막는 물리적 강제. 서비스는 "대체로 됨"으론 부족하다

## 파이썬/개념
- `json.loads(문자열)` → dict. 모델의 말이 코드가 다루는 데이터가 되는 관문
- dict는 이름으로 꺼낸다: `data["summary"]`. 체이닝: `data["todos"][0]["task"]` (서랍 속 서랍)
- `for x in 목록:` — 목록 순회 (while=조건 반복, for=목록 반복. 스트리밍의 for part in stream과 동일)
- f-string 안의 dict 키는 작은따옴표: `{todo['task']}` (바깥 큰따옴표와 충돌 방지)
- f-string에서 진짜 중괄호는 `{{` `}}` 두 번
- JSON 스키마: type/properties/required로 "출력은 이 모양"을 선언하는 설계도

## 사고 기록
- 삼중따옴표 열고 안 닫음 → 아래 코드가 통째로 문자열에 삼켜짐. 여닫이 짝 확인
- prompt에서 `{text}` 누락 → 회의록 없이 "회의록에서 뽑아줘"라고 시킬 뻔 (조용히 틀리는 유형)
- IndentationError 3회차 — 이제 지도 없이 자력 해결
