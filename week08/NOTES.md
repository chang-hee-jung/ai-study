# 8주차 배운 것 (Claude 정리)

## 청킹 (체크포인트 답)
- 문서를 의미 단위(문단)로 자른다. `text.split("\n\n")` = 빈 줄 기준 = 문단 청킹
- **너무 크면**: 한 조각에 여러 주제가 섞여 좌표가 흐려지고, 검색돼도 무관한 내용까지 배달(토큰 낭비)
- **너무 잘게**: "단, 예외로 한다" 같은 조각만 잡히면 뭐의 예외인지 맥락 상실
- 제목만 있는 조각(6~11자)은 정보 없는 소음 → 20자 미만 필터로 제거.
  프로의 해법은 제목을 하위 문단에 붙이기("제2장 휴가 > 연차는...") — 9주차 개선 후보

## 인덱스 구축과 검색의 분리
- `PersistentClient(path=...)` — 디스크 저장 (Client()는 메모리라 껐다 켜면 증발)
- 구축(비싼 배치 작업)과 검색(싼 조회)을 파일 둘로 분리 — DB의 적재/조회 분리와 같은 설계
- `get_collection` = 만들어진 컬렉션 불러오기. 재실행 대비 delete 후 create 패턴
- 벡터 DB 파일(week08/db)은 .gitignore — 산출물은 커밋하지 않는다 (rules.txt에서 재생성 가능)

## 검색 품질 실험 (3전 3승)
- "숙박비 얼마까지" → 출장 조각 (0.480, 압도적 격차)
- "생일에 뭐 나와?" → 복지 조각 ("나와"↔"지급" 매칭)
- **"비번"** → "비밀번호" 조각 — 준말도 넘는다. 키워드 검색이 절대 못 하는 것
- 거리의 절대값은 질문마다 기준이 다름 — 조각들끼리의 **상대 비교**가 중요

## 파이썬
